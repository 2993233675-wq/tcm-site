# 沁春堂国医馆 · 中医问诊网站

一个纯静态的中医诊所宣传 + 在线问诊预约网站。所有页面与交互都是 HTML / CSS / JavaScript，
**不需要服务器、不需要数据库、不需要付费**，可以直接用 GitHub Pages 免费发布上线。

---

## 一、这个网站包含什么

| 文件 | 作用 |
|---|---|
| `index.html` | 首页：品牌介绍、特色科室、就诊流程、经典医案 |
| `services.html` | 六大科室详情（内科、妇科、针灸推拿、儿科、皮肤科、治未病） |
| `doctors.html` | 坐诊医师介绍 + 本周坐诊时间表 |
| `constitution.html` | 九种体质自测（可交互答题，自动判定结果） |
| `consult.html` | 在线问诊表单（带校验，提交后生成问诊单号，可打印/复制） |
| `privacy.html` | 隐私政策与免责声明 |
| `assets/css/style.css` | 全站共用样式表 |
| `assets/js/main.js` | 全站共用脚本（导航、页脚年份等） |
| `assets/js/constitution.js` | 体质自测的题目数据与打分逻辑 |
| `assets/js/consult.js` | 问诊表单的校验与回执生成逻辑 |

**两个交互功能：**

1. **体质自测** —— 9 道题，每题 4 个选项，每题 9 道题答完自动统计各体质得分，得分最高的即为结果，
   并给出该体质的典型表现与日常调养建议。支持"重新测评"。
2. **在线问诊** —— 必填项校验（姓名、性别、年龄、手机号格式、主诉字数、病程、知情同意），
   校验不通过会红色提示并自动滚动到第一个出错的字段。提交成功后生成问诊单号（如 `QCT-20261124-3584`），
   显示完整回执，可打印或复制成文字。

## 二、本地预览（在电脑上先看效果）

### 方法 A：直接双击（最简单）

双击 `index.html`，浏览器就会打开网站。

> 注意：直接双击是用 `file://` 协议打开的，页面能正常显示和交互，
> 但个别浏览器在 `file://` 下会限制本地存储。如果"体质自测"或"问诊提交"出现问题，用下面的方法 B。

### 方法 B：起一个本地服务器（推荐）

在项目文件夹的地址栏输入 `cmd` 回车，会打开命令行窗口，然后输入：

```
python -m http.server 8899
```

再打开浏览器访问 `http://127.0.0.1:8899`。

> 想停止服务器，在命令行窗口按 `Ctrl + C`。

### 方法 C：用 VS Code 打开

1. 打开 VS Code → 菜单 `文件` → `打开文件夹` → 选中 `中医问诊网站` 这个文件夹
2. 安装扩展 **Live Server**（左下角扩展按钮，搜索 `Live Server` 安装）
3. 右键 `index.html` → `Open with Live Server`

## 三、发布到 GitHub（免费上线）

### 第 0 步：注册 GitHub 账号（如果还没有）

1. 打开 https://github.com
2. 右上角点 **Sign up**
3. 填邮箱、设密码、选用户名（**用户名会成为你的网址**，比如用户名 `zhangsan`，
   以后你的网站就在 `zhangsan.github.io`）
4. 去邮箱点验证邮件里的链接，激活账号

### 第 1 步：新建仓库

1. 登录后，点右上角的 **+** 号 → **New repository**
2. 填写：
   - **Repository name**：`tcm-site`（只能用英文小写字母、数字、短横线）
   - **Description**：随便写，比如 `沁春堂国医馆在线问诊网站`
   - **Public**（必须选 Public，私有仓库无法免费开启 Pages）
   - 不要勾选 "Add a README file"
3. 点 **Create repository**

### 第 2 步：上传网站文件

1. 在仓库页面找到 **uploading existing files** 链接（蓝色大字）
2. 把 `中医问诊网站` 文件夹**整个拖进浏览器窗口**

   > ⚠️ 拖拽时注意：拖进去的是**文件夹里的内容**（`index.html`、`services.html`、
   > `doctors.html`、`constitution.html`、`consult.html`、`privacy.html`、`assets` 文件夹），
   > **不要**把外层的 `中医问诊网站` 文件夹本身拖进去，也不要拖 `node_modules`、
   > `package.json`、测试脚本和截图（那些是我本地测试用的，不用上传）。

3. 浏览器下方会显示已上传的文件列表，确认有 `index.html` 和 `assets` 文件夹
4. 页面下方找到 **Commit changes** 按钮，点它

### 第 3 步：开启 GitHub Pages

1. 仓库左侧菜单点 **Settings**
2. 左侧栏往下找到 **Pages**（在 "Code and automation" 分组下）
3. **Source** 部分：
   - Build and deployment → Source 选 **Deploy from a branch**
   - **Branch** 选 `main`，目录选 `/ (root)`
4. 点 **Save**
5. 页面会提示 "Your site is live at ..."，等 1–3 分钟让 GitHub 完成构建

### 第 4 步：访问你的网站

浏览器打开：

```
https://你的用户名.github.io/tcm-site/
```

例如用户名是 `zhangsan`，就是 `https://zhangsan.github.io/tcm-site/`。

> 刚开通时可能显示 404 白色页，这是 GitHub 还在构建。**等待 1–3 分钟再刷新**即可。

## 四、以后怎么修改网站

### 方式 A：在 GitHub 网页上直接改（最简单）

1. 进入你的仓库，点击文件名（比如 `index.html`）
2. 点击文件右上角的铅笔图标 ✏️
3. 直接修改文字，改完点页面底部的 **Commit changes**
4. 等 1–2 分钟，刷新网站就能看到新内容

### 方式 B：在 VS Code 里改（适合大改）

1. VS Code 打开项目文件夹
2. 改文件，保存（`Ctrl + S`）
3. 上传到 GitHub 有两种做法：
   - **装 Git**（推荐，长期用）：到 https://git-scm.com/downloads 下载安装，
     然后在项目文件夹里执行 `git init` → `git add .` → `git commit -m "更新"`
     → `git push`
   - **拖拽法**：把改好的文件重新拖到仓库的 `uploading existing files` 页面，
     覆盖同名文件，再点 Commit changes

## 六、加 AI 智能问诊（第二阶段）

当前版本是**纯静态**的，问诊单提交后数据只存在你自己的浏览器里，不会发送到任何服务器。
等网站跑通、有了真实访客之后，再考虑接入 AI 对话。

接入 AI 需要额外准备（这是第二阶段的事，先把上面的跑通）：

1. **一个后端服务** —— 因为 API 密钥不能写进网页（写进去的话任何人都能看到你的密钥并盗刷）。
   免费方案：Cloudflare Workers、Render 免费额度、或你自己的服务器。
2. **调用 Claude API** —— 你已经有 `cloud.hongqiye.com` 的中转接入，
   在后端用它即可，避免浏览器直连带来的跨域和密钥泄露问题。
3. **医疗安全约束** —— AI 输出必须带免责声明、不做诊断结论、异常症状引导就医。

## 七、常见问题

**Q：上传后 404？**
A：确认 Source 的分支选的是 `main`、目录是 `/ (root)`；确认 `index.html` 在仓库根目录而不是
子文件夹里；然后等 1–3 分钟刷新。

**Q：样式乱了，图片/图标不显示？**
A：检查 `assets` 文件夹是否真的上传上去了（要在仓库里能看到 `assets` 文件夹，
里面还有 `css` 和 `js`）。另外检查文件名大小写 —— 网页引用区分大小写，
`Style.css` 和 `style.css` 是两个不同的文件。

**Q：手机上打开排版乱了？**
A：网站已经写了手机端适配。如果还乱，检查 `style.css` 最后那段 `@media (max-width: 760px)`
有没有被删掉。

**Q：表单提交后数据去哪了？**
A：当前是演示版，数据存在浏览器本地（localStorage），关掉页面就没了。
要做真实的数据收集，需要接后端或第三方表单服务。

**Q：能改成中英文双语吗？**
A：可以。最简单的做法是每个页面再复制一份改语言，加个语言切换按钮。
想要更好的维护性，可以把文案抽到 JS 文件里做成数据驱动。
